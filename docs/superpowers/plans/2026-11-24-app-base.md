# Base de la app Expo (etapa 4b) — plan de implementación

> **Para agentes:** SUB-SKILL REQUERIDO: superpowers:executing-plans (o subagent-driven-development). Los pasos usan casillas (`- [ ]`).

**Objetivo:** crear `app/`, la app Expo sobre la que se construyen el salón, la sala y la mesa, con ingreso por canje, perfil, eliminación de cuenta y exportación web en `/app/`.

**Arquitectura:** la lógica de ingreso (PKCE, retorno, canje y almacenamiento) vive en módulos puros de TypeScript sin React Native, probados con `node --test` desde `tests/unit/`. Un solo archivo, `app/src/api/cliente.ts`, habla con la API: agrega `Authorization: Bearer` en las apps y usa la cookie en la web; la parte 4a lo reemplaza por `paquetes/cliente`. Las pantallas de Expo Router solo conectan esos módulos con `expo-web-browser`, `expo-secure-store` y `expo-crypto`.

**Tecnología:** Expo SDK 58 (React Native 0.88.1), Expo Router, TypeScript, `expo-web-browser`, `expo-secure-store`, `expo-crypto`, `@expo-google-fonts/dm-sans` y `@expo-google-fonts/dm-serif-text`; Nginx (local) y Caddy (producción); Playwright.

**Diseños:** [plan general](../specs/2026-11-23-app-movil-design.md), [servidor para la app](../specs/2026-11-24-servidor-app-design.md), [mesa nueva](../specs/2026-11-24-mesa-nueva-design.md) (paleta y tipografías) y el [plan de la etapa 4](2026-11-24-etapa-4-app-expo.md).

## Restricciones globales

- Expo SDK vigente (58.0.x), builds de desarrollo (`expo-dev-client`), Expo Router, TypeScript. No se usa Expo Go.
- `react` y `react-dom` en **19.3.1**, la misma versión de la raíz (Astro), para que npm no instale dos React en el monorepo. Expo 58 pide 19.3.0: la diferencia es de parche.
- Esquema `eltruco`, retorno `eltruco://ingreso`. Identificador `co.eltru.app` en iOS y Android. Orientación vertical.
- Ingreso nativo: `GET /api/auth/login?app=<desafío>` (desafío = SHA-256 base64url del verificador, 43 caracteres), retorno `eltruco://ingreso?codigo=<código>`, `POST /api/auth/canje` con `{codigo, verificador}` → `{sesion, jugador, bajaCancelada}`. 401 = «El ingreso venció. Volvé a ingresar.»
- La sesión nativa se guarda en `expo-secure-store` con la clave `truco.sesion`. En la web no se guarda nada: manda la cookie `truco_sesion` (`Path=/api/`) del mismo origen.
- Web: ingresar navega a `/api/auth/login?volver=/app/`. El servidor agrega `/app/` a los regresos permitidos.
- Perfil: ID de jugador, nombre, «Cerrar sesión» (`POST /api/auth/logout`) y «Eliminar mi cuenta» (`POST /api/cuenta/eliminar`) con confirmación que explica los 30 días de gracia.
- Exportación web en `/app/` (`experiments.baseUrl: "/app"`, `web.output: "single"`), con vuelta a `/app/index.html` para rutas profundas. `/jugar/` sigue siendo Astro.
- Paleta: papel `#faf8f0`, tinta `#233d31`, acento `#a34b34`, paño `#3a614a → #1c392d`. Tipografías: DM Serif Text (títulos) y DM Sans (texto).
- Textos en español rioplatense. Sin salón, sala ni mesa del diseño (4c y 4d).

## Revisión: casos que ninguna prueba cubre por sí sola

1. El jugador cierra el navegador del sistema sin ingresar: la app vuelve a la pantalla de ingreso sin error ni sesión a medias. → prueba de `completarIngreso` con resultado `cancel`.
2. Un retorno con otro esquema, otra ruta o sin código (otra app abre `eltruco://`): se descarta sin llamar al canje. → pruebas de `codigoDeRetorno`.
3. La sesión guardada venció o se eliminó la cuenta en otro dispositivo: `/api/jugador` responde 401, la app borra la sesión guardada y muestra el ingreso. → prueba de `cargarJugador`.
4. El cierre de sesión falla por red: la sesión local se borra igual, para no dejar al jugador atrapado. → prueba de `cerrarSesion`.
5. Una ruta profunda de la web (`/app/mesa`) recargada en el navegador: el servidor entrega la app, no un 404. → `curl` en `verificar-stack.sh` contra Nginx y contra la imagen de Caddy.

### Tarea 2: PKCE, retorno y almacenamiento (TDD)

**Archivos:**
- Crear: `app/src/ingreso/pkce.ts`, `app/src/ingreso/retorno.ts`, `app/src/ingreso/almacen.ts`
- Prueba: `tests/unit/app-ingreso.test.ts`

**Interfaces:**
- `base64url(bytes: Uint8Array): string`
- `crearPar(aleatorio: (n: number) => Uint8Array, sha256: (texto: string) => Promise<Uint8Array>): Promise<{ verificador: string; desafio: string }>` — 32 bytes aleatorios → verificador de 43 caracteres.
- `codigoDeRetorno(url: string): string | null` — solo `eltruco://ingreso?codigo=<43 base64url>`.
- `interface Guardado { leer(clave): Promise<string | null>; guardar(clave, valor): Promise<void>; borrar(clave): Promise<void> }`; `crearAlmacenSesion(guardado: Guardado)` → `{ leer(), guardar(sesion), borrar() }` sobre la clave `truco.sesion`.

- [ ] Pruebas que fallan:
  - `crearPar` con el verificador del RFC 7636 (bytes del apéndice B) da `E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM`, y `verificadorCorresponde` de `api/sesion.ts` acepta el par.
  - `crearPar` con `node:crypto` da un desafío que `esDesafio` acepta.
  - `codigoDeRetorno` acepta el retorno válido y rechaza `otroapp://ingreso?codigo=…`, `eltruco://otra?codigo=…`, `eltruco://ingreso`, un código corto y un texto que no es URL.
  - `crearAlmacenSesion` guarda, lee y borra en `truco.sesion` y devuelve `null` sin sesión.
- [ ] Implementar, pruebas en verde, commit.

### Tarea 3: cliente mínimo y sesión (TDD)

**Archivos:**
- Crear: `app/src/api/cliente.ts`, `app/src/ingreso/sesion.ts`
- Prueba: `tests/unit/app-ingreso.test.ts`

**Interfaces:**
- `app/src/api/cliente.ts` (único archivo que conoce la API; lo reemplaza 4a):
  - `type Jugador = { id: string; nombre: string }`
  - `class ErrorDeApi extends Error { estado: number }`
  - `crearCliente({ base, sesion, pedir = fetch }: { base: string; sesion: () => Promise<string | null>; pedir?: typeof fetch })` → `{ url(ruta), jugador(): Promise<Jugador | null>, canjear(codigo, verificador): Promise<{ sesion: string; jugador: Jugador; bajaCancelada: boolean }>, cerrarSesion(): Promise<void>, eliminarCuenta(): Promise<{ vence: string }>, abrirSocket(ruta): Promise<WebSocket> }`.
  - Con sesión agrega `Authorization: Bearer <sesión>`; sin sesión usa `credentials: "same-origin"` (web). `cerrarSesion` usa `redirect: "manual"` porque la web responde 303. `abrirSocket` pasa el encabezado con el tercer argumento de React Native.
- `app/src/ingreso/sesion.ts`:
  - `completarIngreso({ resultado, verificador, cliente, almacen }: { resultado: { type: string; url?: string } … })` → `Jugador | null` — `null` si el navegador se cerró o el retorno no sirve; si no, canjea y guarda.
  - `cargarJugador({ cliente, almacen })` → `Jugador | null`; ante 401 borra la sesión guardada.
  - `cerrarSesion({ cliente, almacen })` — borra la sesión local aunque el pedido falle.
  - `eliminarCuenta({ cliente, almacen })` → `{ vence }` y borra la sesión local.

- [ ] Pruebas que fallan con un `fetch` falso: encabezado Bearer con sesión; sin sesión, sin encabezado y con `credentials`; canje con el cuerpo `{codigo, verificador}`; `completarIngreso` con `cancel` y con retorno ajeno no canjea; con retorno válido guarda la sesión; `cargarJugador` con 401 borra; `cerrarSesion` con error de red borra igual; `eliminarCuenta` llama `POST /api/cuenta/eliminar` y borra.
- [ ] Implementar, verde, commit.
