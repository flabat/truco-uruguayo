# Implementación y aceptación

1. **Configuración y persistencia.** Agregar la configuración opcional para servidor, categoría y token en la API y en los servicios de Compose correspondientes. El token se obtiene de los secretos del entorno. Crear una migración compatible con mesas existentes para el vínculo, estado de creación y limpieza. Documentar activación, desactivación y recuperación.
2. **Solicitud de voz.** Incorporar una operación POST autenticada para una mesa. Reutilizar la comprobación de sesión, origen y asiento de las rutas de mesas. Encapsular el cliente HTTP de Discord con límites de tiempo, manejo de permisos y límites de frecuencia. Resolver creación simultánea, caída entre creación y persistencia, renovación de enlaces, eliminación manual y limpieza según la ADR 0002.
3. **Interfaz.** Mostrar el control opcional en la sala y durante la partida en los formatos disponibles. Avisar que la sala es abierta. Mantener acceso por teclado, foco, estado pendiente y reintento. Permitir abrir Discord en móvil y escritorio aunque el navegador bloquee ventanas emergentes después de una solicitud asíncrona.
4. **Pruebas locales.** Con dos sesiones de prueba sentadas en la misma mesa, comprobar que llegan al mismo canal. Con otra mesa, comprobar que el destino cambia. Verificar sesión ausente, asiento ajeno, origen inválido, solicitudes concurrentes, fallos y respuesta perdida, invitación caducada, limpieza y preservación de Mesa 1. Usar un proveedor simulado para pruebas repetibles. Verificar la interfaz en móvil y escritorio, y que las jugadas funcionan si Discord falla.
5. **Prueba con el bot instalado.** Usar una mesa desechable, la API real del juego y el servidor y la categoría configurados. Pedir voz desde dos sesiones de prueba sentadas y verificar en Discord el mismo ID de canal con tipo voz y categoría correcta. Utilizar una segunda mesa para verificar aislamiento. Probar limpieza solo de los canales creados durante el ensayo. Registrar resultados sin enlaces de invitación ni secretos. Separar esta verificación de una prueba acústica con personas. Usar la credencial existente o una que el propietario entregue por un canal seguro. Si falta, documentar exactamente qué quedó pendiente y completar las verificaciones independientes.
6. **Entrega.** Ejecutar npm ci, npm run check y git diff --check. Ejecutar los ensayos con PostgreSQL y Compose si están disponibles. Incluir capturas y resultados reales en el PR. El responsable del repositorio confirma la integración. El despliegue necesita la configuración del bot en el entorno de la API.
